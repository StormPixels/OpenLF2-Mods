## C4 gempa 5XXYY: nilai benar, tafsir diubah
Aturan DOCX: x = XX-50, y = YY-50. Contoh `55200` (XX=52, YY=00) akan memberi y = -50 tetap, padahal contoh dimaksudkan menggeser kiri-kanan saja. Keputusan [BELUM PASTI]: sumbu yang ditulis `00` tidak bergerak; sumbu lain memakai basis 50 (`55200` -> x +2, y 0; `54800` -> x -2, y 0; `55149` -> x +1, y -1). Nama field: `match.st.quake_x`, `match.st.quake_y`, bilangan bulat, satuan piksel, nilai offset untuk tick itu (x positif = peta digeser ke kanan, y positif = ke bawah), 0 bila tidak ada frame gempa; diset ulang ke 0 di awal setiap tick sebelum item dijalankan. Penggambaran: AI 4.

## Putaran 4: koreksi dari uji ponsel pada paket putaran 3
- **C2 (tidak bangkit): penyebab sebenarnya ketemu.** `animation.advance` hanya membuat petarung kalah "berkedip" (`blink` = 30 tick) bila `follow >= 0`, tim musuh, atau indeks > 19. Pemain (indeks < 8) tidak pernah berkedip, sedangkan kebangkitan di `frame_rules.after_physics` menunggu `blink` 1 sampai 4, jadi perbaikan putaran 3 tidak pernah terpenuhi untuk pemain. Perbaikan: petarung dengan `value.st.reserve` dan `lives >= 2` ikut berkedip (satu syarat di `animation.lua`). Tes: `st_flow_test` memainkan kematian lewat tick penuh (gagal di kode putaran 3, lulus sekarang), termasuk kebangkitan kedua dan "tanpa 4xxx tetap mati" dan "lives 1 tetap mati". Alasan tes putaran 3 lolos: memanggil `after_physics` langsung dengan `blink = 3` tanpa menjalankan jalur yang menyetel `blink`.
- **C8 (tidak ada objek): data uji, bukan kode.** `objects.lua` `spawn_point` hanya memunculkan objek bila `parent.wait_counter == 0`, yaitu frame yang dicapai lewat `next`; frame yang dimasuki langsung dari tombol (`hit_a` dan sejenisnya) tidak memunculkan apa pun. Frame uji saya dimasuki langsung dari tombol. Sekarang tiap tes C8 (dan kamera 99XXX) lewat satu frame perantara (wait 1) menuju frame yang membawa opoint. Tes baru `st_spawn_test` memakai `objects.lua` dan `item.record` asli: opoint di frame masuk-tombol tidak memunculkan bola, di frame hasil `next` memunculkan; lalu `hit_Fa` 24/25/26/5219/6220/8224 menghasilkan jumlah objek yang tertulis di panduan.
- **C7 (6XXX, tahan A tidak berubah): kemungkinan besar tombol hanya diketuk.** Aturan DOCX: tombol harus sudah tertahan saat frame dimasuki. Panduan putaran 3 kurang jelas ("lalu A, tahan A"). Pengetesan: tombol yang dilepas dalam 8 tick pertama (ketukan) kini dilupakan dan frame menunggu tekanan berikutnya yang ditahan; setelah itu pelepasan mengakhiri charge seperti sebelumnya. Panduan sekarang menyuruh menahan tanpa melepas. Bila masih tidak berubah padahal ditahan terus dari tekanan pertama, itu bug lain yang belum bisa saya lihat di sandbox; laporkan `6XXX-A` dengan keterangan "ditahan terus".
- **hit_Fa 26 (api melayang): diperbaiki.** Salinan logika ledakan lama menaruh api tanah di ketinggian objek (`y_int - 1`); itu benar di mode lama karena bolanya sudah di tanah, tetapi bola uji muncul di udara. Sekarang api tanah dibuat di `y = -1` dengan `vy = 0`, ledakan tetap di posisi objek. Tes: `st_p2_test` (bola di y -40).

Ledakan `hit_Fa 26` sekarang dibuat di `y = 2` (bukan di ketinggian objek), api tanah tetap di `y = -1`; keduanya tanpa kecepatan vertikal. Sprite nyala 109 berjangkar tinggi (`centery` 148), jadi tampilannya naik dari tanah dengan sendirinya.
